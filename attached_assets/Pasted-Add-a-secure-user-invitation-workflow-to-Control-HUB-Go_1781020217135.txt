Add a secure user invitation workflow to Control HUB.

Goal:
I want to create users by entering their name, email, organization access, and role. The system should send them an email invitation so they can set their own password.

Important:
Users should NOT be able to choose their own role or organization.
Only an Admin / Global Admin / Organization Admin should assign roles and organizations.

Do not email temporary passwords.
Do not force me to manually create passwords for users.
Do not break existing users/passwords.

1. User Invitation Workflow

Add a new workflow:

Admin creates/invites user:
- Full name
- Email address
- Organization access
- Role per organization
- Title
- Department
- Status

Then Admin clicks:
Send Invitation

The system sends the user an email with a secure link to set their password.

3. User Statuses

Add or update user statuses:

- Invited
- Pending Setup
- Active
- Suspended
- Deactivated

Behavior:
- Invited = invitation email sent, password not yet created
- Pending Setup = account exists but password/MFA setup incomplete
- Active = user completed password setup and can log in
- Suspended/Deactivated = cannot log in

4. Invitation Token

Create a secure invitation token system.

Invitation token requirements:
- cryptographically random
- single-use
- expires after 7 days by default
- stored hashed in the database
- never store raw token
- never log raw token
- invalidated after password is created
- invalidated if Admin cancels invite
- regenerated when Admin resends invite

Create an email template.

Subject:

Email body should include:

Hello [Full Name],

You have been invited to access Control HUB.

Your assigned organization:
[Organization Name]

Your assigned role:
[Role Name]

To finish setting up your account, click the secure link below and create your password:

[Set Password Button]

If you were not expecting this invitation, you can ignore this email.

Thanks,
Control HUB

This page should:

- allow user to create password

- submit password setup

8. Password Policy

Require:
- minimum 12 characters
- at least one uppercase letter
- at least one lowercase letter
- at least one number
- at least one special character

Recommended:
- block common passwords if simple to implement

After password setup:
- hash password securely using existing password hashing method
- mark invitation accepted
- mark user Active
- redirect to login page with success message:
“Your password has been set. You may now sign in.”

15. Backend API Endpoints

Add or update:

POST /api/users/invite
- creates user
- assigns organization/role
- creates invitation token
- sends email

POST /api/users/:id/resend-invite
- regenerates token
- sends email

POST /api/users/:id/cancel-invite
- cancels invitation

GET /api/invitations/validate?token=
- validates token and returns safe invite metadata

POST /api/invitations/accept
- validates token
- sets password
- activates user

PATCH /api/users/:id
- edit user information and org roles

DELETE /api/users/:id
- delete/deactivate user based on rules

16. Security

Security requirements:
- invitation token must be random and unguessable
- store only token hash
- expire token after 7 days
- token is single-use
- do not expose whether an email exists publicly
- rate limit invitation acceptance attempts
- rate limit password setup attempts
- log failed token attempts
- do not expose roles/orgs beyond what is assigned to the invited user
- do not allow token reuse
