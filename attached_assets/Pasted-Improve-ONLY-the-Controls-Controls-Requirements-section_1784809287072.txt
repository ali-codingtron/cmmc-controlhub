Improve ONLY the Controls / Controls & Requirements section by adding multiple useful views.

Current issue:

The Controls page currently presents one flat list of all controls. The list is useful for detailed searching, but it is not the easiest way for regular users to understand:

- progress by security domain
- which controls need attention
- which controls have evidence
- which controls have complete narratives
- which controls have monitoring or POA&M issues
- how requirements are grouped when multiple compliance packages are selected

Goal:

Add several selectable views that use the same existing organization-specific control data.

Do not create duplicate controls.

Do not change any current:

- control status
- implementation narrative
- evidence mapping
- SSP narrative
- monitoring record
- POA&M record
- owner
- organization package assignment
- production data

This is primarily a Controls-section user-interface and query enhancement.

====================================================================
1. PAGE NAME AND PURPOSE
====================================================================

Keep the sidebar label:

Controls

Use the page title:

Controls & Requirements

Subtitle:

“Review implementation progress, supporting evidence, monitoring, SSP coverage, and remediation status across the organization’s selected compliance packages.”

If the organization only uses CMMC, the page may continue to display CMMC terminology.

If the organization uses multiple frameworks, display:

- CMMC controls
- NIST requirements
- assessment objectives
- DFARS obligations
- custom requirements

using the selected organization packages.

====================================================================
22. MOST IMPORTANT DESIGN RULE
====================================================================

The views are different ways to display the same underlying organization-control data.

Do not create separate control records, statuses, evidence links, or progress values for each view.

Recommended user experience:

- Domain Overview answers: “Where do we stand?”
- Detailed Table answers: “Show me every requirement.”
- Readiness Matrix answers: “What is complete or missing for each control?”
- Attention Needed answers: “What should we work on next?”
- Package View answers: “How do the selected frameworks compare?”
