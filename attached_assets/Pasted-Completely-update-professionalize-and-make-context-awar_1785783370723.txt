Completely update, professionalize, and make context-aware ONLY the Control HUB Help & User Guide module.


Current observed problems:

1. The Help Center displays the same categories, articles, FAQs, workflows, and videos regardless of the logged-in user’s effective role.

2. Help content is not filtered by:
   - platform role
   - organization-specific role
   - effective permissions
   - selected organization
   - active compliance packages
   - enabled organization modules

3. A CMMC Level 1 organization can still see articles such as DFARS Contract Obligations even when DFARS is not assigned.

4. Pre-Assessment help is displayed even when Pre-Assessment may be disabled for the organization.

5. The Control Detail Tabs article is outdated and does not reflect the current Control Detail functionality, including Tasks and the newer control views.

6. The User Roles Guide reflects an older simplified role model and does not properly explain:
   - Platform Role None
   - Platform Global Admin
   - organization-specific roles
   - different roles in different organizations
   - effective permissions
   - protected break-glass behavior

7. The How to Invite a New User guide assumes one user role and one organization assignment and does not reflect the current membership model.

8. Several help tags and labels are displayed in lowercase or inconsistent capitalization, including examples such as:
   - dfars
   - users
   - documents
   - poams

9. Video Tutorials is mostly disabled “Coming Soon” cards, which makes the application look incomplete.

10. Contact Support currently points users to info@carmetechnology.com rather than providing a real support-ticket workflow.

11. Article pages are visually plain:
   - long blocks of text
   - no useful table of contents
   - limited hierarchy
   - weak related-content navigation
   - no role/package context
   - no professional callouts or step styling

12. The Help landing page contains too much empty background space and many visually identical cards.

Goal:

Create a professional Control HUB Help Center that:

- shows each user only the content relevant to their effective role
- also respects active packages and enabled modules
- accurately reflects currently implemented functionality
- provides professional articles, FAQs, workflows, and videos
- includes a real Submit Support Ticket workflow
- sends support tickets to support@carmetechnology.com
- uses consistent capitalization and terminology
- remains easy to maintain as Control HUB changes

28. EMAIL FAILURE HANDLING
====================================================================

Do not show a false success when email delivery fails.

Preferred workflow:

1. Create the ticket transactionally.
2. Attempt support email delivery.
3. Record delivery status.
4. Retry failed delivery through a controlled background retry process.
5. Show the user the actual result.

Successful message:

“Support request submitted successfully.”

Show:

- Ticket Number
- Submitted Date
- View My Support Requests

Delivery delayed:

“Your support request was recorded, but email delivery is delayed. Support delivery will be retried.”

Failed record creation:

“Your support request could not be submitted. No ticket was created.”

Do not expose Resend API details or stack traces.
