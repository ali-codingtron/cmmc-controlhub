Improve the Implementation Roadmap UX so it is easier for regular users to understand and follow.

I attached a video showing the current Implementation Roadmap workflow. The section is functional, but it feels confusing for a normal user. It looks more like a technical data list than a guided action plan.

Goal:
Make the Implementation Roadmap feel like a guided CMMC implementation workplan.

The user should immediately understand:
- what action to do first
- why that action matters
- what controls it supports
- what evidence/documents it will produce
- what steps they need to complete
- how progress is calculated
- what “done” means
- what to do next

Do not remove existing functionality. Reorganize and improve the user experience.

====================================================================
1. RENAME AND REFRAME THE PAGE
====================================================================

Current:
Implementation Roadmap

Keep the name, but add a clearer subtitle:

“Follow high-impact actions that build evidence and documentation across multiple CMMC controls.”

Add a short explanation near the top:

“Instead of working control-by-control, this roadmap groups related implementation work into actions that support multiple CMMC controls at once.”

Add a small info tooltip for:
- Impact Score
- Controls Covered
- Full Support
- Partial Support
- Evidence Needed
- Ready for Review

====================================================================
2. ADD A “START HERE” PANEL
====================================================================

At the top of the roadmap page, add a prominent “Start Here” panel.

This should show:

- Recommended first action
- Why it is first
- Controls impacted
- Estimated effort
- Expected outputs
- Start Action button

Example:

Start Here:
Configure Endpoint Compliance and Device Management

Why this is recommended:
This action supports 12 controls across Configuration Management, Access Control, System and Information Integrity, and Identification and Authentication.

Expected outputs:
- device inventory
- Intune compliance screenshots
- security baseline evidence
- antivirus status evidence
- encryption evidence

Button:
Start This Action

If a user already started an action, show:
Continue Current Action

If all actions are complete, show:
Roadmap Complete

13. AUTO-CALCULATE ACTION PROGRESS
====================================================================

Do not rely only on manual progress status.

Action progress should be calculated from:

- steps completed
- required evidence uploaded
- required documents present
- validation completed
- checklist complete
- blockers open

Example:
Action Progress = 65%

Show breakdown:
- Steps: 7/10
- Evidence: 4/6
- Documents: 2/3
- Validation: 0/1
- Checklist: 8/11

Manual status should still exist, but the app should show why something is or is not complete.

====================================================================
14. IMPROVE STATUS MEANINGS
====================================================================

Show status definitions somewhere on the page.

Statuses:
- Not Started: no work has begun
- In Progress: work has started
- Evidence Needed: steps may be complete but evidence is missing
- Ready for Review: action appears complete and needs review
- Complete: action completed and reviewed
- Blocked: cannot continue due to issue

Automatically suggest:
- Evidence Needed when required evidence is missing
- Ready for Review when all steps/evidence/checklist are complete
- Blocked when a blocker exists
