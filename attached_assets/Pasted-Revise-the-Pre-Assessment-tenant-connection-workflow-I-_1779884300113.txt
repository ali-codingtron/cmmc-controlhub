Revise the Pre-Assessment tenant connection workflow.

I do NOT want a Manual Pre-Assessment module anymore.

Remove:
- Manual Pre-Assessment page
- Manual questionnaire placeholder
- Manual Pre-Assessment navigation item
- Any “Coming Soon” manual assessment messaging

The Pre-Assessment module should be focused on tenant-connected automated assessments.

Important security requirement:
Do NOT collect or store Microsoft admin usernames or passwords in Control HUB.

When I say “connect using admin credentials,” I mean:
- the Microsoft admin should click “Connect Microsoft Tenant”
- they should be redirected to Microsoft’s official sign-in/admin consent page
- they authenticate directly with Microsoft
- Control HUB never sees or stores the admin password
- after admin consent, Control HUB receives permission to perform read-only Microsoft Graph scans

1. Replace App-Only Manual Credential Form

Current issue:
The connection form asks for:
- Microsoft Tenant ID
- App Registration Client ID
- Client Secret

I do not want customers to manually create an app registration or enter client secrets.

Remove these fields from the customer-facing form:
- App Registration Client ID
- Client Secret

Keep optional/read-only fields after connection:
- tenant name
- tenant ID
- primary domain
- connected by
- connected date
- permission status
- last scan date

2. Use Control HUB Multi-Tenant App

Implement tenant connection using a Control HUB-owned Microsoft multi-tenant app registration.

The app should be configured once by Control HUB, not by every customer.

Use environment variables for the Control HUB app:

- MICROSOFT_CLIENT_ID
- MICROSOFT_CLIENT_SECRET or certificate credential
- MICROSOFT_REDIRECT_URI
- MICROSOFT_AUTHORITY = https://login.microsoftonline.com/organizations

The customer should only click:
“Connect Microsoft Tenant”

Then Microsoft handles:
- admin sign-in
- MFA
- consent
- tenant authorization

3. Admin Consent Flow

Implement a Microsoft admin consent flow.

When user clicks “Connect Microsoft Tenant”:
- generate a secure state value
- store organization_id in the state server-side
- redirect to Microsoft admin consent URL
- request read-only Graph application permissions
- return to callback URL
- validate state
- capture tenant ID from Microsoft response
- save tenant connection

Use Microsoft-supported OAuth/admin consent flow.

Do not ask the user to paste secrets.

6. No Tenant Write Access

Do not request write permissions.

Do not request:
- Directory.ReadWrite.All
- Application.ReadWrite.All
- Policy.ReadWrite.*
- DeviceManagementManagedDevices.ReadWrite.All
- User.ReadWrite.All
- Group.ReadWrite.All

This assessment must be read-only.

7. App Registration Clarification

Customers should not create an app registration.

Control HUB should use one multi-tenant app registration owned by Control HUB.

When the customer admin consents:
- Microsoft creates the Enterprise Application / service principal in their tenant automatically
- Control HUB stores the tenant connection
- Control HUB can run read-only scans using the granted permissions

- use server-side token acquisition
- store only tenant connection metadata and scan results
- support disconnect/revoke

- allow re-run admin consent

- mark that assessment pack as unavailable
- continue scanning other packs
