Rebuild Control HUB into a framework/package-driven compliance platform.

Goal:
When creating an organization, the user should be able to choose which compliance package(s) apply to that organization. Based on the selected package(s), the app should display the correct controls, requirements, evidence needs, documentation needs, reports, dashboards, roadmap actions, monitoring tracker items, and assessment language.

Control HUB should support CMMC, NIST SP 800-171, NIST assessment packages, and DFARS contract obligation packages.

Important:
Do not damage or modify existing production data.
Do not change existing VTCCORP.US controls, evidence, documents, SSP, monitoring, POA&M, users, or reports unless explicitly approved.
This should be implemented as a new framework/package architecture that can coexist with current CMMC L2 data.

====================================================================

====================================================================

The app should no longer assume every organization is only CMMC L2.

Each organization should have one or more selected compliance packages.

Examples:

20. HELP AND FAQ
====================================================================

- difference between CMMC, NIST, DFARS, FAR
- difference between controls and contract obligations
- how to change selected packages
- how crosswalks work

Add FAQ:

Q: Why do controls change when I select a package?
A: Each package has its own requirements. Control HUB displays the requirements applicable to the selected package(s).

Q: Can one organization have multiple packages?
A: Yes. For example, an organization can select NIST 800-171 Rev. 2, CMMC Level 2 Self-Assessment, and DFARS 7012.

Q: Are DFARS clauses controls?
A: No. DFARS clauses are contract obligations. Control HUB tracks them as obligations mapped to evidence, documents, reports, and related controls.

Q: Can the same evidence support multiple packages?
A: Yes. Evidence can be linked to multiple controls, NIST requirements, assessment objectives, or DFARS obligations.
