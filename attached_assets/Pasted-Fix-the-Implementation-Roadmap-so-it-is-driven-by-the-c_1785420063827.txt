Fix the Implementation Roadmap so it is driven by the compliance packages selected for each organization.

Current issue:

An organization that has only CMMC Level 1 selected is currently seeing the CMMC Level 2 Implementation Roadmap.

The current roadmap contains Level 2 actions, controls, evidence requirements, and terminology that do not apply to a Level 1-only organization.

This is misleading and must be corrected.

Goal:

The Implementation Roadmap must dynamically select the correct roadmap profile based on the active compliance packages assigned to the organization.

Never show a Level 2 roadmap merely because no Level 1 roadmap profile exists.

7. LEVEL 1 ROADMAP ACTIONS
====================================================================

Create approximately these Level 1 roadmap actions.

--------------------------------------------------------------------
ACTION 1 — DEFINE FCI SCOPE AND SYSTEM INVENTORY
--------------------------------------------------------------------

Purpose:

Identify where FCI is processed, stored, or transmitted and document the systems, users, devices, facilities, and external connections within the Level 1 assessment scope.

Expected outputs:

- FCI scope statement
- system inventory
- user inventory
- device inventory
- network boundary summary
- public-facing system inventory
- assessment scope approval

Do not require a Level 2 CUI SSP unless the organization separately selected a package that requires one.

--------------------------------------------------------------------
ACTION 2 — CONFIGURE AUTHORIZED ACCESS
--------------------------------------------------------------------

Support Level 1 access-control requirements.

Include:

- identify authorized users
- identify authorized devices
- restrict system access
- restrict transactions and functions
- control external system connections
- control information posted to public systems

Expected evidence:

- authorized-user list
- device inventory
- access-role matrix
- external connection review
- public-information review procedure
- access validation test

--------------------------------------------------------------------
ACTION 3 — IMPLEMENT IDENTIFICATION AND AUTHENTICATION
--------------------------------------------------------------------

Include:

- identify users
- identify processes acting on behalf of users
- identify devices
- authenticate users, processes, and devices before access

Expected evidence:

- user account export
- device inventory
- authentication policy
- login test results
- account ownership records

Do not automatically add Level 2 MFA requirements unless another active package requires them.

--------------------------------------------------------------------
ACTION 4 — PROTECT AND SANITIZE MEDIA
--------------------------------------------------------------------

Include:

- identify media containing FCI
- protect media
- sanitize or destroy media before disposal or reuse
- document sanitization methods and records

Expected evidence:

- media handling procedure
- media inventory
- sanitization record
- disposal certificate or test record

--------------------------------------------------------------------
ACTION 5 — CONTROL PHYSICAL ACCESS
--------------------------------------------------------------------

Include:

- limit physical access
- escort visitors
- monitor visitor activity
- maintain physical-access logs
- manage physical-access devices

Expected evidence:

- authorized physical-access list
- visitor log
- escort procedure
- key/badge inventory
- facility-access review

Where one canonical CMMC Level 1 requirement maps to multiple NIST assessment rows, show the rows as assessment objectives rather than separate roadmap controls.

--------------------------------------------------------------------
ACTION 6 — PROTECT SYSTEM BOUNDARIES AND PUBLIC COMPONENTS
--------------------------------------------------------------------

Include:

- monitor and protect external boundaries
- monitor and protect key internal boundaries
- separate publicly accessible components from internal systems where applicable

Expected evidence:

- network diagram
- firewall configuration
- boundary-rule review
- public-facing system inventory
- segmentation test

--------------------------------------------------------------------
ACTION 7 — MAINTAIN SYSTEM AND INFORMATION INTEGRITY
--------------------------------------------------------------------

Include:

- identify and correct system flaws
- provide malicious-code protection
- update malicious-code protection
- perform periodic scans
- perform real-time scans of externally sourced files

Expected evidence:

- patch/update report
- vulnerability or flaw-remediation record
- antivirus status
- malware update status
- periodic scan results
- real-time protection configuration

--------------------------------------------------------------------
ACTION 8 — COMPLETE LEVEL 1 SELF-ASSESSMENT AND AFFIRMATION
--------------------------------------------------------------------

Include:

- verify every Level 1 requirement is MET
- verify supporting evidence
- conduct required examine/interview/test activities
- record assessment scope
- record CAGE codes
- prepare SPRS submission information
- prepare affirmation
- retain assessment artifacts for the required retention period

Important:

Level 1 does not permit POA&M use to achieve Final Level 1 status.

If a requirement is Not Met:

- mark the roadmap action Attention Needed
- create a Task or internal remediation action if supported
- do not represent the organization as Level 1 complete
- do not create a formal CMMC Level 1 POA&M completion path
