Create a Smart Evidence Mapping engine for Control HUB.

Purpose:

When a user uploads evidence, Control HUB should analyze the file and recommend the controls, requirements, assessment objectives, or contract obligations that the artifact most likely supports.

After the user confirms the suggested mappings:

- create one Evidence record
- store one physical file
- create one mapping for every confirmed control
- display the evidence automatically under every linked control’s Evidence tab

Do not create duplicate evidence records or duplicate physical files for each linked control.

Do not automatically change a control’s implementation status.

Do not automatically approve evidence.

====================================================================
1. FEATURE NAME AND ROLLOUT MODES
====================================================================

Feature name:

Smart Evidence Mapping

Add these configurable modes:

- Disabled
- Shadow Mode
- Suggestion Mode
- Auto-Link Exact Matches
- Auto-Link High-Confidence Matches

Production defaults:

- Shadow Mode = Enabled
- Suggestion Mode = Enabled after testing
- Auto-Link Exact Matches = Disabled initially
- Auto-Link High-Confidence Matches = Disabled initially
- External AI Processing = Disabled

Definitions:

Shadow Mode:
Analyze files and save suggestions, but do not display or create mappings.

Suggestion Mode:
Show recommendations and require user confirmation.

Auto-Link Exact Matches:
Automatically link only deterministic, exact control-ID matches.

Auto-Link High-Confidence Matches:
Automatically link approved high-confidence classifications after the feature has been validated.

====================================================================
4. ANALYSIS PIPELINE
====================================================================

When a file is selected:

Stage 1 — Temporary File Processing

- place the file in temporary private storage
- validate extension
- validate MIME type
- validate file size
- calculate SHA-256 hash
- preserve original filename
- do not create the final Evidence record yet

Stage 2 — Metadata Extraction

Collect:

- filename
- normalized filename
- title
- extension
- MIME type
- user-selected evidence type
- description
- tags
- organization
- active frameworks/packages
- manually selected controls

Stage 3 — Content Extraction

Extract relevant content based on file type.

PDF:
- text
- headings
- tables
- page titles
- control IDs
- dates

DOCX:
- headings
- paragraphs
- tables
- document metadata

XLSX:
- worksheet names
- column headers
- representative rows
- report titles

CSV:
- headers
- representative rows

TXT / LOG / JSON:
- text
- key names
- representative entries

Images:
- OCR or an approved vision-processing provider
- visible portal names
- policy names
- control IDs
- report headings
- relevant labels

Do not send raw files to an external AI provider unless External AI Processing is explicitly enabled for the organization.

Stage 4 — Candidate Generation

Only evaluate requirements assigned to the active organization.

Candidate sources:

- exact control-ID matches
- filename rules
- metadata rules
- evidence-profile keyword matches
- semantic similarity
- existing confirmed mappings
- framework crosswalks
- AI classifier output

Stage 5 — Candidate Ranking

Return the top five candidates.

Each candidate must include:

- requirement ID
- title
- framework/package
- domain/family
- confidence score
- confidence label
- recommended relationship type
- short mapping reason
- exact terms or profile that matched

====================================================================
5. DETERMINISTIC RULES FIRST
====================================================================

Always run rule-based mapping before semantic AI classification.

Recognize formats such as:

- AC.L1-3.1.1
- AC.L2-3.1.3
- AC-3.1.1
- AC_L1_3_1_1
- IA-3.5.3
- SI-3.14.7
- 3.1.1
- R-05

Mapping priority:

1. Exact full control ID in filename
2. Exact full control ID in extracted content
3. Exact NIST requirement with unambiguous package context
4. Known Control HUB filename pattern
5. Expected-evidence profile match
6. Semantic/content classification
7. Existing approved mapping examples

Do not let semantic AI override an exact control ID without displaying a conflict warning.

====================================================================
6. CONFIDENCE CATEGORIES
====================================================================

Use:

Exact Match:
Deterministic control-ID or approved rule match

High Confidence:
90% to 99%

Medium Confidence:
70% to 89%

Low Confidence:
Below 70%

Initial behavior:

Exact Match:
- preselect
- require final confirmation

High Confidence:
- preselect as Suggested
- require confirmation

Medium Confidence:
- display but leave unselected

Low Confidence:
- place under Possible Matches
- do not select

No Match:
- require manual selection or explicit Unmapped Review decision

Never silently link a Medium- or Low-confidence result.

9. FINAL PLACEMENT
====================================================================

After confirmation:

1. Store the final file in persistent private storage.
2. Create one Evidence record.
3. Create one mapping row per confirmed control.
4. Set one mapping as primary.
5. Commit file, Evidence record, and mappings transactionally.
6. Refresh Evidence Repository.
7. Refresh every linked control’s evidence count.
8. Display the evidence under every linked control’s existing Evidence tab.

Example:

File:
Quarterly_User_Access_Review.xlsx

Confirmed controls:
- AC.L1-3.1.1
- AC.L1-3.1.2
- IA.L1-3.5.1

Expected result:

- one stored file
- one Evidence record
- three mapping rows
- one Evidence Repository row
- evidence visible under all three controls
- organization-wide evidence count increases by one
- each linked control evidence count increases by one

- show related target requirements as optional suggestions
- require explicit user confirmation

For DFARS:

- treat mappings as contract obligations
- do not label them equivalent controls

16. SECURITY REQUIREMENTS
====================================================================

Evidence may contain CUI or other sensitive contract information.

Default security requirements:

- private persistent storage
- temporary private staging
- organization isolation
- no public file URLs
- no raw file contents in application logs
- no external AI processing by default
- no provider training on evidence
- no cross-organization data reuse
- encryption in transit
- encryption at rest
- cleanup of temporary files
- audit logging

If an external AI provider is enabled:

- require explicit organization approval
- record provider name
- record deployment/region
- record retention configuration
- record authorization date
- record responsible approver
- show a CUI-processing warning
- include the provider in the organization’s service-provider inventory
- do not enable globally by accident
