Add evidence upload functionality directly to the organization-level Evidence Repository.

Current situation:

* The Evidence Repository currently has Bulk Download but no Upload Evidence action.
* A user must open an individual control and use its Evidence tab to upload evidence.
* The control-level uploader automatically links the file to the current control.
* I need the Evidence Repository uploader to support linking one uploaded artifact to multiple controls at the same time.

Goal:
From Evidence Repository, an authorized user should be able to:

* upload one evidence file
* bulk upload multiple files
* select multiple linked controls or requirements
* store one physical file and one evidence record
* display that same evidence under every selected control’s Evidence tab
* preview and download it from either location

Do not create duplicate evidence records or duplicate physical files for each selected control.

====================================================================

1. ADD UPLOAD ACTIONS TO EVIDENCE REPOSITORY
    ====================================================================

On the Evidence Repository page, add these actions beside Bulk Download:

* Upload Evidence
* Bulk Upload

Recommended header layout:

Upload Evidence | Bulk Upload | Bulk Download

Upload Evidence:

* uploads one evidence record

Bulk Upload:

* uploads multiple files in one operation

Use the same visual style and underlying upload service currently used by:

Controls > Control Detail > Evidence > Add Evidence / Bulk Upload

Do not build a completely separate uploader with different validation or storage behavior.

====================================================================
2. SINGLE EVIDENCE UPLOAD FORM

When the user clicks Upload Evidence, open a professional modal or full-page form.

Fields:

Required:

* File
* Title
* Evidence Type
* Status
* Linked Controls / Requirements

Optional:

* Description
* Collection Date
* Expiration / Review Date
* Owner
* Assessor Summary
* Internal Notes
* Tags
* Primary Control / Requirement

Evidence statuses:

* Draft
* Pending Review
* Approved
* Active
* Assessor Ready
* Stale
* Archived

Default:
Draft

Use the organization currently selected in the sidebar.

The user must not be able to upload into another organization by changing the request payload.

====================================================================
3. MULTI-CONTROL SELECTION

The Linked Controls / Requirements field must support selecting multiple records.

Use a searchable multi-select control.

Allow search by:

* Control ID
* Requirement ID
* Title
* Security Domain / Family
* Framework
* Package
* Level

Add filters within the selector:

* Framework / Package
* Security Domain / Family
* Level
* CMMC / NIST / DFARS package, where applicable

Selected controls should display as removable chips.

Example:

AC.L1-3.1.1 — Authorized Access Control
IA.L2-3.5.3 — Multifactor Authentication
CA.L2-3.12.3 — Security Control Monitoring

Allow one selected item to be designated as:

Primary Control

The primary control should be used for:

* default security domain
* default level
* exported filename conventions
* primary display grouping

All selected controls must still appear in the evidence metadata and mappings.

====================================================================
4. PACKAGE-AWARE REQUIREMENT SELECTION

Because Control HUB now supports multiple packages, the selector should display only controls and requirements assigned to the current organization.

Examples:

* CMMC controls
* NIST SP 800-171 requirements
* NIST SP 800-171A assessment objectives, if evidence linking is supported
* DFARS obligations

Clearly label each option with a package badge.

Example:

[CMMC L2] AC.L2-3.1.3 — CUI Flow Control

[NIST R2] 3.1.3 — Control CUI Flow

[DFARS 7012] Cyber Incident Reporting Process

Do not display unrelated packages that are not active for the organization.

If equivalent requirements use a shared canonical requirement, do not create duplicate links unnecessarily.

====================================================================
5. EVIDENCE CONTROL-MAPPING MODEL

Use a many-to-many relationship.

One Evidence record may support many controls or requirements.

One control or requirement may have many Evidence records.

Use or update a mapping table similar to:

EvidenceRequirementMap

* id
* evidence_id
* requirement_id
* organization_id
* is_primary
* relationship_type
* linked_by
* linked_at

Relationship types:

* Direct Evidence
* Supporting Evidence
* Reference
* Shared Evidence

Enforce uniqueness:

evidence_id + requirement_id

Do not create duplicate mapping rows.

Do not copy the evidence file for each linked control.

====================================================================
6. EXPECTED DISPLAY AFTER UPLOAD

After successful upload, the evidence must appear in:

1. Evidence Repository
2. Evidence Detail page
3. Evidence tab of every selected control or requirement

Example:

A file linked to:

* AC.L1-3.1.1
* AC.L1-3.1.2
* IA.L1-3.5.1

must appear in all three corresponding Evidence tabs.

The Evidence Repository Linked Controls column should display:

* the primary control
* additional control count

Example:

AC.L1-3.1.1 +2

Hovering or opening the record should show the full list.

Do not create three Evidence records.

====================================================================

After upload:

* refresh the Evidence Repository count
* refresh the evidence count on every linked control

Do not double-count one evidence record in the organization-wide Evidence Repository total just because it is linked to multiple controls.

Organization-wide total:
Count unique Evidence records.

Control-level evidence count:
Count Evidence records mapped to that control.

* Status
