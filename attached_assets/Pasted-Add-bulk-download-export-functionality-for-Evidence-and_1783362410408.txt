Add bulk download/export functionality for Evidence and Documents.

Goal:
Users should be able to download multiple evidence files and documents at once from Control HUB. This is needed for C3PAO review, customer exports, internal audit packages, and offline review.

This should work from:
- Evidence Repository
- Documentation > All Documents
- Control Detail > Evidence tab
- Control Detail > Documents/Documentation section if applicable
- Reports / Export area if useful

Important:
All roles that have permission to view/download evidence or documents should be able to use bulk download, including Assessor Read-Only. However, the download must respect the role’s existing organization and object-level permissions.

Do not allow any user to bulk download records they cannot normally view/download one at a time.

5. File Naming Convention

When exporting, rename the copied files in the ZIP using linked controls.

Do not rename the original file in Control HUB.

Export filename format:

CONTROLID__TYPE__SHORT_TITLE__DATE.ext

Example:
AC.L1-3.1.1__Report__User_Access_Review__2026-07-06.xlsx

For multiple linked controls, use:

PRIMARYCONTROL_PLUS_#_CONTROLS__TYPE__SHORT_TITLE__DATE.ext

Example:
AC.L1-3.1.1_PLUS_4_CONTROLS__Policy__Access_Control_Policy__2026-07-06.docx

The full linked control list must appear in the manifest.

Rules:
- keep filenames under 120 characters
- keep full path under 200 characters where possible
- preserve the original extension
- remove unsafe characters
- replace spaces with underscores
- if duplicate filename exists, append _01, _02, etc.
- include original filename in the manifest

6. Linked Controls in ZIP

Every exported file should clearly show linked controls in at least two ways:

A. Filename includes primary linked control.
B. Manifest includes all linked controls.

If exporting by control folder:
- if one evidence item supports multiple controls, either:
  - copy it into each linked control folder, or
  - store it once and include a shortcut/reference text file

Preferred:
For review packages, copy into each linked control folder.
For import packages, store once and use manifest mapping.

11. Permission Rules

Bulk download must respect permissions.

All roles may bulk download only items they are allowed to view/download.

Role behavior:
- Global Admin: can download all organization data
- Organization Admin: can download all data for assigned organization
- Compliance Manager: can download all data for assigned organization
- IT Contributor: can download evidence/documents they are allowed to view
- Reviewer: can download reviewable evidence/documents
- Executive Viewer: can download reports and approved documents if allowed
- Assessor Read-Only: can bulk download approved/active/assessor-ready evidence and documents for assigned organization
- Demo Viewer: can only download demo/sample files if demo downloads are enabled

Assessor Read-Only should not be able to bulk download Draft or internal-only artifacts unless explicitly allowed.

12. Status Inclusion Rules

Default for assessor/export users:
Include:
- Approved
- Active
- Assessor Ready

Exclude by default:
- Draft
- Pending Review
- Archived
- Stale

Admins can optionally include:
- Draft
- Pending Review
- Archived
- Stale

But the ZIP summary should clearly state which statuses were included.

13. Missing File Handling

If metadata exists but file is missing from storage:
- do not fail the whole export
- add item to Export_Issues.xlsx
- show warning after export

Export_Issues.xlsx columns:
- Record ID
- Title
- Linked Controls
- Original Filename
- Issue
- Recommended Action

Issues:
- file missing from storage
- unsupported file type
- permission denied
- duplicate filename renamed
- filename shortened
- no linked control
- no security domain

20. Security

Do not create public ZIP links.

ZIP downloads must require authentication and authorization.

ZIP files should expire or be cleaned up after a set retention period.

Suggested:
- keep generated ZIPs for 7 days
- allow admin to delete export packages
- do not expose storage paths publicly
- use signed temporary URLs if object storage is used
