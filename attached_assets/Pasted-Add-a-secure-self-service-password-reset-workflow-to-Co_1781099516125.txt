Add a secure self-service password reset workflow to Control HUB.

Goal:
Users should be able to request a password reset from the login page. The system should email them a secure password reset link using the configured email provider.

Important:
- Do not change existing usernames.
- Do not change existing passwords unless the user completes the reset.
- Do not reset passwords automatically.
- Do not expose whether an email address exists in the system.
- Use Resend if EMAIL_PROVIDER=resend is configured.
- Keep the current invitation workflow working.

1. Add “Forgot Password?” to Login Page

On the login page, add a link:

Forgot password?

When clicked, open or navigate to:

/forgot-password

2. Forgot Password Page

Create page:

/forgot-password

Fields:
- Email address

Button:
Send Reset Link

When submitted, always show the same message:

“If an account exists for that email address, a password reset link has been sent.”

Do not reveal whether the email exists.

3. Password Reset Token Model

Create a secure password reset token system.

Add model:

PasswordResetToken
- id
- user_id
- token_hash
- status
- expires_at
- used_at
- requested_at
- requested_ip
- requested_user_agent
- created_at
- updated_at

Statuses:
- Pending
- Used
- Expired
- Revoked

Token requirements:
- cryptographically random
- URL-safe
- single-use
- expires after 30 minutes, or 60 minutes maximum
- store only token hash in the database
- never store raw token
- never log raw token
- revoke existing pending reset tokens for the user when a new one is requested

Use:
crypto.randomBytes(32).toString("base64url")

Hash token before storing:
SHA-256 is acceptable for token lookup.

4. Reset Link Format

Generate reset links like:

https://controlhub.carmetechnology.com/reset-password?token=<token>

Use APP_BASE_URL for production.

If running in dev/preview, use the current request origin so reset links do not point to the wrong environment/database.

5. Email Delivery

Use the existing configured email system.

If EMAIL_PROVIDER=resend:
- use RESEND_API_KEY
- use EMAIL_FROM

Do not require SMTP if Resend is configured.

Subject:
Reset your Control HUB password

Email body:
Hello [First Name],

We received a request to reset your Control HUB password.

Click the button below to create a new password:

[Reset Password]

This link expires in 30 minutes.

If you did not request this reset, you can ignore this email.

Thanks,
Control HUB

Do not include the token visibly except in the reset URL.

6. Reset Password Page

Create page:

/reset-password?token=<token>

Behavior:
- validate token
- if valid, show password reset form
- if expired, show “This password reset link has expired.”
- if already used, show “This password reset link has already been used.”
- if invalid, show “This password reset link is invalid.”

Fields:
- New Password
- Confirm New Password

Add:
- Show password toggle
- Password strength/help text

7. Password Policy

Require:
- minimum 12 characters
- at least one uppercase letter
- at least one lowercase letter
- at least one number
- at least one special character

Recommended:
- block common passwords if feasible
- prevent using the same password as current password if feasible

8. Complete Reset Behavior

When user submits new password:

- verify token is valid and not expired
- verify password policy
- hash password using the existing password hashing method
- update user password_hash
- mark token Used
- set used_at timestamp
- revoke all other pending reset tokens for that user
- reset failed login count
- unlock account if locked
- revoke all existing sessions for that user
- redirect to login page

Show message:
“Your password has been reset. Please sign in with your new password.”

9. MFA Behavior

If the user has MFA enabled:
- password reset does not disable MFA
- user must still complete MFA on next login

If Admin has marked mfa_reset_required:
- keep that separate from password reset

Do not bypass MFA because a password reset occurred.

10. Rate Limiting

Add rate limiting.

Forgot password request:
- limit by IP
- limit by email
- example: 5 requests per hour per email/IP

Reset token validation/submission:
- limit failed attempts
- after repeated failures, temporarily block attempts from that IP/token

Do not allow attackers to brute-force reset tokens.

11. Account Enumeration Protection

For /forgot-password:
- always return the same user-facing message
- use roughly similar response timing whether the email exists or not
- do not show “user not found”
- do not show “email sent” only for valid users

Admin audit logs can record the real result.

12. Audit Logs

Add audit log events:

- password reset requested
- password reset requested for unknown email
- password reset email sent
- password reset email failed
- password reset token validated
- password reset token invalid
- password reset token expired
- password reset completed
- password reset failed
- user sessions revoked after password reset

Each audit log should include:
- user ID if known
- email attempted
- IP address
- user agent
- timestamp
- success/failure
- reason

Do not log:
- raw token
- new password
- password hash

13. Email Settings Integration

If email is not configured:
- show admin warning in Settings > Email
- do not expose this to normal users
- on forgot password, still show generic message
- log that email delivery failed because email is not configured

If Resend is configured:
- send reset email automatically

14. Users Page Admin Actions

On Users page, add Admin action:

Send Password Reset

When Admin clicks it:
- generate password reset token
- email reset link to the user
- do not set a temporary password
- log audit event

Also add:
Copy Password Reset Link

Only if email delivery fails or admin explicitly chooses manual copy.

15. Security Center

Add Security Center widgets:
- password resets requested in last 24 hours
- failed reset attempts
- reset emails failed
- users with recent password reset
- accounts locked/unlocked

16. API Endpoints

Add endpoints:

POST /api/auth/forgot-password
- accepts email
- always returns generic success
- creates reset token if user exists and active
- sends email if configured

GET /api/auth/reset-password/validate?token=
- validates token and returns safe status

POST /api/auth/reset-password
- accepts token, newPassword, confirmPassword
- validates token
- updates password
- invalidates token
- revokes sessions

POST /api/users/:id/send-password-reset
- admin only
- sends reset link to selected user

Make password reset pages match Control HUB branding:

Pages:
- /forgot-password

18. Acceptance Tests

Test A:
Known user requests password reset.
User sees generic success message.
Email is sent through Resend.

Test B:
Unknown email requests password reset.
User sees the same generic success message.
No account enumeration occurs.
Audit log records unknown email attempt.

Test C:
User clicks valid reset link.
Reset password form opens.

Test D:
User enters valid new password.
Password updates.
Token becomes Used.
User can log in with new password.

Test E:
Same reset link cannot be reused.

Test F:
Expired reset link shows expired message.

Test G:
Password reset does not disable MFA.

Test H:
Existing usernames, roles, organizations, and permissions remain unchanged.

Test I:
Admin can send password reset email from Users page.

Test J:
Resend email failures are logged and shown to Admin only.
