Enhance the Implementation Roadmap Operating Procedure section.

Current issue:
The Operating Procedure steps are too high-level. They say things like “Enroll all Windows devices in Microsoft Intune” or “Deploy the Microsoft Security Baseline,” but they do not tell me exactly where to go, what to configure, what screenshots/evidence to capture, what the expected result is, or what to do if the step fails.

Goal:
Each Operating Procedure should become a detailed implementation playbook that walks the user through exactly how to perform the action.

This should be manual guidance only. Do not build Microsoft 365 / Intune / Defender API integrations yet.

1. Replace Simple Bullet Steps With Detailed Procedure Steps

Each operating procedure step should include:

- Step number
- Step title
- Purpose
- System / portal
- Exact navigation path
- Detailed action instructions
- Recommended setting / expected configuration
- Expected result
- Evidence to capture
- Suggested evidence filename
- Related controls
- Owner role
- Completion status
- Notes
- Troubleshooting / if this fails
- Link evidence button

2. Use Expandable Step Cards

Instead of showing only one-line bullets, show each step as an expandable card.

Collapsed view:
- Step number
- Step title
- Status
- Related portal
- Evidence required indicator

Expanded view:
- Purpose
- Detailed instructions
- Navigation path
- Expected result
- Evidence to capture
- Suggested filename
- Related controls
- Notes
- Mark complete
- Upload/link evidence

3. Add Step Status Tracking

Each step should have organization-specific progress:

Statuses:
- Not Started
- In Progress
- Complete
- Blocked
- Not Applicable

Track:
- completed by
- completed date
- notes
- linked evidence

4. Add Evidence Capture Guidance Per Step

For each step, show exactly what evidence should be captured.

Evidence guidance should include:
- evidence type
- screenshot/export/report required
- what must be visible
- recommended filename
- where the evidence should be linked
- suggested evidence status

Example filename format:
CONTROLID_ActionName_YYYY-MM-DD.ext

Example:
CM-3.4.1_Intune_Device_Compliance_Policy_2026-05-10.png

5. Add “If This Fails” Guidance

Each step should include instructions for exceptions or failures.

Examples:
- create POA&M
- create remediation ticket
- mark step Blocked
- document exception
- attach compensating control evidence
- escalate to compliance manager

6. Add Procedure Editor for Admins

Admin and Compliance Manager users should be able to:
- edit procedure steps
- add custom steps
- reorder steps
- mark steps required or optional
- add evidence requirements
- add troubleshooting notes

Assessor users must be read-only.

7. Seed More Detailed Procedure for “Configure Endpoint Compliance and Device Management”

Replace the current high-level steps with detailed steps like this:

Action:
Configure Endpoint Compliance and Device Management

Category:
Endpoint Security

Step 1: Confirm Endpoint Scope

Purpose:
Identify which devices are in scope for CMMC and CUI access.

System / Portal:
Control HUB, Intune Admin Center, asset inventory

Navigation:
Control HUB > Assessment Scope / Assets
Intune Admin Center > Devices > All Devices

Instructions:
- Review the organization’s in-scope asset inventory.
- Identify all Windows endpoints that store, process, or access CUI.
- Confirm each device has an assigned owner.
- Confirm each device appears in Intune or the approved management platform.
- Identify unmanaged, stale, duplicate, or unknown devices.
- Document any devices that require remediation or exclusion.

Expected Result:
All CUI-scoped devices are identified, owned, and listed in the asset inventory.

Evidence to Capture:
- device inventory export
- screenshot of Intune All Devices filtered to in-scope devices
- asset inventory showing assigned owner and scope

Suggested Filename:
CM-3.4.3_Device_Inventory_YYYY-MM-DD.xlsx

Related Controls:
- CM.L2-3.4.3
- IA.L1-3.5.1
- AC.L2-3.1.18

If This Fails:
Create a POA&M or remediation task for unmanaged or unknown devices.

Step 2: Enroll Devices in Intune

Purpose:
Ensure in-scope endpoints are centrally managed.

System / Portal:
Microsoft Intune Admin Center

Navigation:
Intune Admin Center > Devices > Windows > Windows enrollment

Instructions:
- Confirm enrollment method is configured.
- Confirm users or device groups are assigned to enrollment policies.
- Verify existing devices are enrolled.
- Identify devices not enrolled.
- For missing devices, initiate enrollment or document approved exception.
- Confirm enrollment status is current.

Expected Result:
All in-scope Windows endpoints are enrolled or have documented exceptions.

Evidence to Capture:
- enrollment policy screenshot
- enrolled device list
- exception list if applicable

Suggested Filename:
CM-3.4.1_Intune_Enrollment_Status_YYYY-MM-DD.png

Related Controls:
- CM.L2-3.4.1
- CM.L2-3.4.2
- AC.L2-3.1.18

Step 3: Create Device Compliance Policy

Purpose:
Require managed devices to meet baseline security requirements.

System / Portal:
Microsoft Intune Admin Center

Navigation:
Devices > Compliance policies > Policies > Create Policy

Instructions:
- Create or review Windows compliance policy.
- Require BitLocker or device encryption.
- Require active antivirus.
- Require firewall enabled.
- Require OS version or patch compliance.
- Require TPM where applicable.
- Assign policy to in-scope device group.
- Save policy and confirm assignment.

Recommended Settings:
- BitLocker required
- Antivirus required
- Firewall required
- Secure boot/TPM preferred where supported
- Mark devices noncompliant if policy evaluation fails

Expected Result:
Compliance policy exists and is assigned to in-scope devices.

Evidence to Capture:
- policy settings screenshot
- assignment screenshot
- compliance summary screenshot

Suggested Filename:
CM-3.4.2_Device_Compliance_Policy_YYYY-MM-DD.png

Related Controls:
- CM.L2-3.4.2
- SI.L1-3.14.2
- SI.L1-3.14.5
- AC.L2-3.1.18
