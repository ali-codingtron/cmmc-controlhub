Add a new module called “Implementation Roadmap.”

Purpose:
This section should show me which high-impact actions I should perform first to make progress across multiple CMMC Level 2 controls.

This should help me answer:
- What should I do first?
- Which controls does this action support?
- What evidence should I capture?
- Where should the evidence be linked?
- What documents should be created or updated?
- What tests should be performed?
- Which controls become fully supported, partially supported, or still missing items?

Important:
Do not say that one action automatically “closes” a control.
Use the terms:
- Supports
- Partially Supports
- Evidence Collected
- Documentation Collected
- Ready for Review
- Candidate for Implemented

A control should only become Implemented if all required conditions are met:
- implementation narrative exists
- SSP narrative exists
- required evidence exists
- evidence is approved/current
- required policy/procedure exists where applicable
- testing/validation is complete where applicable
- no blocking POA&M exists

Effort levels:
- Low

3. Action Impact Scoring

Create an impact score for each roadmap action.

Suggested formula:
- +3 points for every control directly supported
- +2 points for every control partially supported
- +2 points for every missing evidence item it helps create
- +2 points for every missing document it helps create
- +1 point for every monitoring activity it helps satisfy
- -1 to -5 points based on complexity/effort

Display:
- Impact Score
- Estimated Effort
- Recommended Order

Example:
Action: Perform User Access Review
Impact Score: 42
Effort: Medium
Controls Supported: 12
Recommended Priority: High

4. Action Detail Page

Each action should have a detailed page with these sections:

A. Purpose
Explain what this action accomplishes.

B. Why This Action Matters
Explain why this should be done early and what compliance areas it supports.

C. Linked Controls
Show all controls supported by this action.

For each control show:
- control ID
- control title
- domain
- level
- support type:
  - Full Support
  - Partial Support
  - Evidence Only
  - Documentation Only
  - Monitoring Only
- current control status
- evidence status
- documentation status

D. Operating Procedure
Step-by-step instructions for performing the action.

E. Test Procedure
Step-by-step instructions for validating that the action worked.

F. Evidence to Capture
List all evidence that should be captured.

For each evidence item show:
- evidence title
- evidence type
- suggested file name
- source system
- what must be visible
- linked controls
- linked assessment objectives, if available
- recommended status

G. Documents to Create or Update
Show required documents:
- policy
- procedure
- review log
- checklist
- approval record
- risk record
- POA&M if needed

H. Completion Checklist
Checklist items:
- action performed
- evidence captured
- evidence uploaded
- evidence approved
- documents uploaded/updated
- test performed
- exceptions documented
- POA&M created if needed
- affected controls reviewed

I. Result
Allow setting action result:
- Passed
- Passed with Exceptions
- Failed
- Needs Follow-Up

If result = Failed:
- require POA&M creation or linkage

10. Integration with Evidence

When evidence is uploaded from a roadmap action:
- link it to all mapped controls automatically
- allow user to remove controls if needed
- auto-tag evidence with:
  - action name
  - domain
  - control IDs
  - evidence type
  - review date

11. Integration with Documents

When a document is uploaded or created from a roadmap action:
- link it to all mapped controls
- show where it satisfies policy/procedure requirements
- include it in Documentation > All Documents

12. Integration with Monitoring Tracker

If a roadmap action is recurring:
- link it to the Monitoring Tracker
- show last completed
- next due
- current/overdue status

13. Do Not Auto-Mark Implemented Without Validation

The system may recommend that controls are ready for review, but it should not automatically mark a control Implemented unless readiness rules are met.

Readiness rules:
- SSP narrative exists
- required evidence exists and is approved
- required documents exist and are approved
- testing is complete where applicable
- monitoring is current where applicable
- no blocking POA&M exists

14. Acceptance Tests

Test A:
- Open Implementation Roadmap
- See high-impact actions sorted by priority and impact score

Test B:
- Open Perform User and Access Review
- See linked controls, required documents, evidence to capture, operating procedure, test procedure, and completion checklist

Test C:
- Upload evidence from the User Access Review action
- Evidence is linked to all mapped controls
- Evidence appears under each control’s Evidence tab

Test D:
- Complete an action
- Related controls show Partial Support or Ready for Review, not automatically Implemented unless all readiness rules are satisfied

Test E:
- Open a control
- See which roadmap actions support that control
