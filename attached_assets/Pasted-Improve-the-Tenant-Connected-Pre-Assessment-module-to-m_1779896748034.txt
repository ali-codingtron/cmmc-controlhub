Improve the Tenant-Connected Pre-Assessment module to make it look and function like a professional client-facing assessment tool.

The current scan works, but it needs a better scan experience, clearer scoring, better findings workflow, better evidence handling, and professional reporting.

1. Add Scan Progress Experience

When a user clicks Run Tenant Assessment, show a scan progress modal/page.

Progress stages:
- Initializing scan
- Validating Microsoft tenant connection
- Checking granted permissions
- Running Identity Pack
- Running Authentication Pack
- Running Conditional Access Pack
- Running Audit / Sign-in Pack
- Running Secure Score Pack
- Running Device / Intune Pack
- Generating evidence snapshots
- Generating findings
- Generating evidence requests
- Generating roadmap recommendations
- Finalizing scan results

Each stage should show:
- status: Pending, Running, Complete, Warning, Failed, Skipped
- progress percentage
- details
- timestamp
- error message if applicable

If one pack fails, continue the scan and show that pack as Failed or Unavailable instead of failing the entire scan.

2. Rename Readiness Score

Do not call the Microsoft tenant scan score simply “Readiness Score.”

Rename it to:

Tenant Scan Health

or:

Microsoft Tenant Technical Readiness

Add separate metrics:
- Tenant Scan Health
- CMMC Control Coverage
- Assessment Confidence
- Data Coverage

Do not imply this is an official CMMC score.

3. Add Scope and Limitations Section

Add a card on the Summary tab:

Assessment Scope & Limitations

Text:
“This tenant-connected pre-assessment reviews Microsoft tenant configuration and Microsoft Graph data available through granted read-only permissions. It does not replace a C3PAO assessment and does not fully determine CMMC compliance. Final readiness still requires SSP review, policies, procedures, evidence review, interviews, testing, POA&M review, and non-Microsoft system validation.”

7. Add Affected Objects to Findings

Each finding should support an affected objects section.

Examples:
For MFA Registration Coverage:
- list users missing MFA registration

For Stale Account Review:
- list stale users, disabled users, no sign-in users

For Unique Named Accounts:
- list accounts that matched shared/generic naming patterns

For Sign-in Logs:
- list failed/risky sign-in samples

For Directory Audit Logs:
- list role changes, user/group changes, policy changes

Allow export of affected objects.
