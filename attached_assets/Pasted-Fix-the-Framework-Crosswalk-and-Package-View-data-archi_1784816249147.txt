Fix the Framework Crosswalk and Package View data architecture.

Current production behavior:

1. Framework Crosswalk returns:
   “No crosswalk mappings between these packages”
   when comparing:

   NIST SP 800-171 Rev. 2
   to
   NIST SP 800-53 Rev. 4

   - NIST SP 800-171 Rev. 2 — 110 Controls
   - NIST SP 800-53 Rev. 4 — 0 Controls
   - DFARS 252.204-7012 — 0 Controls

This indicates that package assignments exist, but the required reference-control, crosswalk, and DFARS obligation data is either missing, incorrectly keyed, or being queried from the wrong tables.

Correct the Framework Crosswalk and Package View without modifying existing organization implementation data.

- implementation narratives
- evidence
- evidence mappings
- SSP narratives
- monitoring records
- POA&M records
- control owners

6. USE GLOBAL CROSSWALK DATA
====================================================================

Framework Crosswalk must use global mapping data.

It should not require the organization to have separate implementation-status records for every target reference control.

Correct behavior:

APEX Solutions has NIST 800-171 Rev. 2 assigned.

NIST 800-53 Rev. 4 is enabled as a reference catalog.

The crosswalk should still display the official mappings, even if APEX Solutions is not independently implementing the complete 800-53 catalog.

Organization-specific readiness should be overlaid separately.

The crosswalk query should:

1. Resolve Package A.
2. Resolve Package B.
3. Load global mappings between the package IDs.
4. Load source and target requirement/control metadata.
5. Optionally overlay organization implementation status.
6. Return mapping rows.

Do not filter out a global mapping merely because the target control has no OrganizationRequirementStatus record.
