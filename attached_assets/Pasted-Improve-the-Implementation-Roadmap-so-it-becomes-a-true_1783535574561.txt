Improve the Implementation Roadmap so it becomes a true guided implementation workflow, not just a roadmap list.

I reviewed the updated roadmap in production. It is better, but it is still confusing for a normal user.

Current issues:
1. The Priority Actions page does not clearly explain how the roadmap works.
2. The page does not explain why completing roadmap actions is beneficial.
3. The stage tracker appears on action detail pages, but there is no clear way to complete each tracker stage.
4. The progress/status box is disconnected from the actual steps, evidence, documents, validation, and checklist.
5. The steps are still too generic. They need to be much more detailed and actionable.
6. Users need to know exactly what to do, what to upload, how to validate it, and how to know when the action is complete.

Goal:
Make the Implementation Roadmap feel like a guided CMMC implementation assistant.

The roadmap should answer:
- What should I do first?
- Why does this action matter?
- Which controls does it support?
- What evidence will I create?
- What documents will I need?
- What exact steps do I perform?
- How do I validate it?
- How do I mark it complete?
- What happens next?

12. REPLACE GENERIC STEPS FOR “PERFORM USER AND ACCESS REVIEW”
====================================================================

For the roadmap action “Perform User and Access Review,” replace generic steps with detailed steps.

Use this structure:

Step 1: Export All Active Users

Purpose:
Create a current user inventory for review.

Systems Used:
Microsoft Entra Admin Center

Navigation:
Microsoft Entra Admin Center > Identity > Users > All Users

Detailed Instructions:
1. Open https://entra.microsoft.com.
2. Sign in with an administrative account.
3. Navigate to Identity > Users > All Users.
4. Review the user list.
5. Add or verify columns for:
   - Display Name
   - User Principal Name
   - Account Enabled
   - User Type
   - Department
   - Job Title
   - Last Sign-In if available
6. Export the user list.
7. Save the export using the suggested filename.
8. Upload the file to Control HUB and link it to this roadmap action and related controls.

Expected Result:
A current user inventory exists and can be reviewed for authorized access.

Evidence to Capture:
- user export CSV/XLSX
- screenshot of All Users page
- list of disabled/guest/stale accounts if applicable

Suggested Filename:
AC-3.1.1_User_Inventory_YYYY-MM-DD.xlsx

Linked Controls:
AC.L1-3.1.1
AC.L1-3.1.2
IA.L1-3.5.1

Validation:
Confirm every active user has a business purpose and no unauthorized users exist.

Common Mistakes:
- exporting users but not reviewing them
- not including guest users
- not documenting disabled or stale accounts
- not saving the review evidence

Step 2: Review Privileged Roles

Systems Used:
Microsoft Entra Admin Center

Navigation:
Identity > Roles and Administrators

Detailed Instructions:
1. Open Entra Admin Center.
2. Navigate to Identity > Roles and Administrators.
3. Review Global Administrator, Privileged Role Administrator, Exchange Administrator, SharePoint Administrator, Security Administrator, and Intune Administrator roles.
4. Export or screenshot each relevant role assignment.
5. Confirm every privileged user has documented approval.
6. Identify excessive or unnecessary privileged access.
7. Document remediation actions.

Evidence:
- privileged role assignment export
- screenshots of role membership
- approval records for admin access

Suggested Filename:
AC-3.1.1_Privileged_Role_Review_YYYY-MM-DD.xlsx

Linked Controls:
AC.L2-3.1.5
AC.L2-3.1.6
AC.L2-3.1.7
IA.L1-3.5.1

Step 3: Review Guest and External Users

Navigation:
Identity > Users > All Users > Filter User Type = Guest

Detailed Instructions:
1. Filter users by User Type = Guest.
2. Review each guest account.
3. Confirm business justification.
4. Confirm sponsor/owner.
5. Remove or disable unauthorized guests.
6. Export guest user list or document “no guest users found.”

Evidence:
- guest user export
- guest access approval list
- screenshot showing guest user filter

Suggested Filename:
AC-3.1.1_Guest_User_Review_YYYY-MM-DD.xlsx

Step 4: Review Stale and Disabled Accounts

Detailed Instructions:
1. Review accounts with no recent sign-in.
2. Review disabled accounts.
3. Determine whether accounts should remain, be removed, or be documented as exceptions.
4. Record decision and owner.
5. Document remediation.

Evidence:
- stale account review worksheet
- disabled account export
- remediation tickets

Suggested Filename:
AC-3.1.1_Stale_Account_Review_YYYY-MM-DD.xlsx

Step 5: Cross-Reference HR / Authorized User List

Detailed Instructions:
1. Obtain HR roster or approved user list.
2. Compare active Entra users to approved personnel.
3. Identify users not on HR roster.
4. Identify terminated users.
5. Document exceptions.

Evidence:
- access review worksheet
- HR roster comparison
- exception list

Step 6: Review Group Memberships for CUI Access

Navigation:
Identity > Groups > All Groups

Detailed Instructions:
1. Identify groups that provide access to CUI systems, SharePoint sites, Teams, repositories, or admin portals.
2. Export group membership.
3. Confirm each member has authorized need.
4. Remove unauthorized members.
5. Document approvals or exceptions.

Evidence:
- group membership export
- access review worksheet
- change/removal evidence

Step 7: Document Access Review Results

Detailed Instructions:
1. Complete access review worksheet.
2. Record reviewer name and date.
3. Record findings.
4. Record removed users or access changes.
5. Record exceptions and approvals.
6. Upload final signed/reviewed worksheet.

Evidence:
- completed access review worksheet
- signed approval
- access change tickets

Step 8: Upload and Link Evidence in Control HUB

Detailed Instructions:
1. Open Control HUB.
2. Navigate to Implementation Roadmap > Perform User and Access Review.
3. Open Evidence to Collect.
4. Upload each required evidence item.
5. Confirm linked controls are preselected.
6. Save evidence as Approved or Pending Review depending on workflow.

Step 9: Validate Control Coverage

Detailed Instructions:
1. Open Controls Supported tab.
2. Review linked controls.
3. Confirm evidence appears under each related control.
4. Open AC.L1-3.1.1 and confirm evidence is visible.
5. Repeat for key IA and AC controls.

Step 10: Complete Checklist and Mark Ready for Review

Detailed Instructions:
1. Open Checklist tab.
2. Complete required checklist items.
3. Add notes for any exceptions.
4. Confirm evidence and documents are linked.
5. Set action status to Ready for Review.
